# Статические проверки API v2

`POST /api/v2/check` выполняет только явно запрошенные детекторы и возвращает
найденные сигналы. Сервис не принимает решение о том, является ли сообщение
спамом: поле `has_signals` означает лишь наличие хотя бы одного найденного
сигнала.

## Общий формат

Тело запроса содержит текст, список детекторов и их параметры:

```json
{
  "text": "Текст сообщения",
  "detectors": ["blacklist", "links", "phone"],
  "options": {
    "blacklist": {"words": ["casino"]},
    "links": {},
    "phone": {}
  }
}
```

Успешный ответ всегда имеет следующий верхнеуровневый формат:

```json
{
  "has_signals": true,
  "signal_count": 3,
  "results": []
}
```

- `has_signals` — `true`, если любой запрошенный детектор что-либо нашёл;
- `signal_count` — сумма найденных сущностей; для `message_length` это 1 при
  выходе длины за диапазон и 0 в остальных случаях;
- `results` — результаты в порядке, указанном в `detectors`;
- у всех результатов, кроме `message_length`, `detected` равно `count > 0`.
  У `message_length` поле `count` содержит длину текста, а `detected` означает
  выход за заданный диапазон. `confidence` равно `1.0`: это уверенность
  детектора в результате, а не оценка опасности сообщения.

## `blacklist`

**Что делает.** Ищет в тексте слова из переданного списка по вхождению
подстроки.

**Пример запроса.**

```json
{
  "text": "CASINO casino! Приходите в casino.",
  "detectors": ["blacklist"],
  "options": {
    "blacklist": {"words": ["casino", "free"]}
  }
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 1,
  "results": [
    {
      "name": "blacklist",
      "detected": true,
      "confidence": 1.0,
      "count": 1,
      "details": {
        "hits": ["casino"],
        "occurrences_count": 3
      }
    }
  ]
}
```

**Особенности.**

- Параметр `options.blacklist.words` обязателен: от 1 до 1000 непустых слов,
  каждое длиной до 128 символов.
- Текст и слова нормализуются Unicode NFKC и приводятся к регистронезависимому
  виду (`casefold`). Поэтому `CASINO` и `casino` считаются одним совпадением.
- `hits` содержит уникальные нормализованные слова в порядке запроса;
  `count` — их число. `occurrences_count` содержит количество всех
  непересекающихся вхождений найденных слов в текст.

## `links`

**Что делает.** Извлекает HTTP- и HTTPS-ссылки из текста.

**Пример запроса.**

```json
{
  "text": "Подробнее: https://example.org/info, а также http://example.org/faq.",
  "detectors": ["links"],
  "options": {"links": {}}
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 2,
  "results": [
    {
      "name": "links",
      "detected": true,
      "confidence": 1.0,
      "count": 2,
      "details": {
        "links": [
          "https://example.org/info",
          "http://example.org/faq"
        ]
      }
    }
  ]
}
```

**Особенности.**

- Параметры не поддерживаются: необходимо передавать пустой объект `{}` либо
  не указывать `options.links` вовсе. В частности, legacy-параметр `max_links`
  отклоняется.
- Распознаются только URL с префиксом `http://` или `https://`.
- Повторяющиеся ссылки удаляются с сохранением первого появления. Знаки
  пунктуации `.,;:!?)]}` в конце URL не включаются в результат.
- При обнаружении более 100 уникальных ссылок возвращается HTTP 422; список не
  обрезается.

## `phone`

**Что делает.** Находит номера России/Казахстана, Узбекистана и Беларуси и
возвращает их в нормализованном международном формате.

**Пример запроса.**

```json
{
  "text": "Звоните: 8 (912) 345-67-89, +998 90 123-45-67 или +375 (29) 123-45-67.",
  "detectors": ["phone"],
  "options": {"phone": {}}
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 3,
  "results": [
    {
      "name": "phone",
      "detected": true,
      "confidence": 1.0,
      "count": 3,
      "details": {
        "phones": [
          "+79123456789",
          "+998901234567",
          "+375291234567"
        ]
      }
    }
  ]
}
```

**Особенности.**

- Параметры не поддерживаются: передаётся пустой объект `{}` либо
  `options.phone` можно не указывать.
- Для РФ/Казахстана распознаются номера с началом `+7`, `7` или `8`; для
  Узбекистана — `+998`, для Беларуси — `+375`. Разрешены пробелы, круглые
  скобки и дефисы в ожидаемых позициях.
- Номера приводятся к международному цифровому виду (например,
  `8 (912) 345-67-89` → `+79123456789`), дедуплицируются и сохраняют порядок
  первого появления.
- Добавочные номера и несоответствующие шаблонам короткие номера не
  извлекаются. Проверка не оценивает существование или достоверность номера.
- При обнаружении более 100 уникальных номеров возвращается HTTP 422; список
  не обрезается.

## `telegram_nick`

**Что делает.** Извлекает Telegram-имена пользователей.

**Пример запроса.**

```json
{
  "text": "Напишите @support_user или @sales_team.",
  "detectors": ["telegram_nick"]
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 2,
  "results": [
    {
      "name": "telegram_nick",
      "detected": true,
      "confidence": 1.0,
      "count": 2,
      "details": {"nicknames": ["@support_user", "@sales_team"]}
    }
  ]
}
```

**Особенности.** Параметры не поддерживаются. Ник должен начинаться с `@` и
состоять из 5–32 букв ASCII, цифр или символов `_`. Повторы сохраняются.

## `message_length`

**Что делает.** Сигнализирует, что длина сообщения находится вне заданного
диапазона.

**Пример запроса.**

```json
{
  "text": "Коротко",
  "detectors": ["message_length"],
  "options": {"message_length": {"min_length": 10, "max_length": 2000}}
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 1,
  "results": [
    {
      "name": "message_length",
      "detected": true,
      "confidence": 1.0,
      "count": 7,
      "details": {"length": 7, "min_length": 10, "max_length": 2000}
    }
  ]
}
```

**Особенности.** Параметры необязательны; по умолчанию используются
`min_length: 10` и `max_length: 2000`. `count` всегда равен длине текста,
а `detected` равен `true`, только если длина меньше `min_length` или больше
`max_length`. Вклад этого детектора в `signal_count` равен 1 при обнаружении
сигнала и 0 иначе. Значение `min_length` не может быть больше `max_length`.

## `email_addresses`

**Что делает.** Извлекает адреса электронной почты по простому шаблону.

**Пример запроса.**

```json
{
  "text": "Контакт: sales@example.org",
  "detectors": ["email_addresses"]
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 1,
  "results": [
    {
      "name": "email_addresses",
      "detected": true,
      "confidence": 1.0,
      "count": 1,
      "details": {"emails": ["sales@example.org"]}
    }
  ]
}
```

**Особенности.** Параметры не поддерживаются. Детектор выполняет только
синтаксическое извлечение и не подтверждает, что почтовый ящик существует.

## `emoji_check`

**Что делает.** Извлекает эмодзи из поддерживаемых Unicode-диапазонов.

**Пример запроса.**

```json
{
  "text": "Скидка 😀😀",
  "detectors": ["emoji_check"],
  "options": {"emoji_check": {"max_emoji": 10}}
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 2,
  "results": [
    {
      "name": "emoji_check",
      "detected": true,
      "confidence": 1.0,
      "count": 2,
      "details": {"max_emoji": 10, "emoji_count": 2, "emojis": ["😀😀"]}
    }
  ]
}
```

**Особенности.** `max_emoji` необязателен и по умолчанию равен 10; он
возвращается для совместимости с настройками v1, но не ограничивает и не
фильтрует результат v2. `count` и `emoji_count` содержат число кодовых точек
в найденных группах эмодзи.

## `async_exemple`

**Что делает.** Передаёт текст внешнему HTTP-сервису и преобразует его поле
`passed` в сигнал: `true` означает обнаруженный сигнал, `false` — отсутствие
сигнала.

**Пример запроса.**

```json
{
  "text": "Сообщение для внешней проверки",
  "detectors": ["async_exemple"],
  "options": {
    "async_exemple": {
      "url": "https://detector.example/check",
      "timeout": 2.0,
      "payload": {"source": "chat"}
    }
  }
}
```

**Пример ответа внешнего сервиса.**

```json
{"passed": true, "score": 0.8}
```

**Пример ответа `/api/v2/check`.**

```json
{
  "has_signals": true,
  "signal_count": 1,
  "results": [
    {
      "name": "async_exemple",
      "detected": true,
      "confidence": 1.0,
      "count": 1,
      "details": {"url": "https://detector.example/check", "status_code": 200}
    }
  ]
}
```

**Особенности.** Поддерживаются `url`, `api_key`, `timeout` (более 0 и до 60 с),
`fail_on_error` и объект `payload`; текст всегда записывается в поле `text`
исходящего JSON. При ошибке сети, не-200 ответе или некорректном JSON сигнал
отсутствует, если не задано `fail_on_error: true`. В ответ v2 не передаются
API-ключ, отправленный текст, payload и тело внешнего ответа.

## Ограничения и ошибки валидации

- `text` — строка не длиннее 20 000 символов.
- В `detectors` должен быть хотя бы один из восьми допустимых детекторов;
  повторения запрещены. Максимум — восемь детекторов.
- Неизвестные поля и параметры, опции для незапрошенного детектора, а также
  отсутствие `blacklist.words` для детектора `blacklist` приводят к HTTP 422.
- При превышении лимита сущностей ответ имеет HTTP 422 и тело вида:

```json
{
  "detail": {
    "code": "detection_limit_exceeded",
    "message": "links detector found more than 100 unique links"
  }
}
```
