# Статические проверки API v2

`POST /api/v2/check` выполняет только явно запрошенные детекторы и возвращает
найденные сигналы. Сервис не принимает решение о том, является ли сообщение
спамом: поле `has_signals` означает лишь наличие хотя бы одного найденного
сигнала.

## Общий формат

Тело запроса содержит текст, список детекторов и их параметры:

```json
{
  "text": "Текст сообщения",
  "detectors": ["blacklist", "links", "phone"],
  "options": {
    "blacklist": {"words": ["casino"]},
    "links": {},
    "phone": {}
  }
}
```

Успешный ответ всегда имеет следующий верхнеуровневый формат:

```json
{
  "has_signals": true,
  "signal_count": 3,
  "results": []
}
```

- `has_signals` — `true`, если любой запрошенный детектор что-либо нашёл;
- `signal_count` — сумма `count` всех результатов;
- `results` — результаты в порядке, указанном в `detectors`;
- у каждого результата `detected` всегда равно `count > 0`, а `confidence`
  равно `1.0`: это уверенность детектора в результате, а не оценка опасности
  сообщения.

## `blacklist`

**Что делает.** Ищет в тексте слова из переданного списка по вхождению
подстроки.

**Пример запроса.**

```json
{
  "text": "CASINO casino! Приходите в casino.",
  "detectors": ["blacklist"],
  "options": {
    "blacklist": {"words": ["casino", "free"]}
  }
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 1,
  "results": [
    {
      "name": "blacklist",
      "detected": true,
      "confidence": 1.0,
      "count": 1,
      "details": {
        "hits": ["casino"],
        "occurrences_count": 3
      }
    }
  ]
}
```

**Особенности.**

- Параметр `options.blacklist.words` обязателен: от 1 до 1000 непустых слов,
  каждое длиной до 128 символов.
- Текст и слова нормализуются Unicode NFKC и приводятся к регистронезависимому
  виду (`casefold`). Поэтому `CASINO` и `casino` считаются одним совпадением.
- `hits` содержит уникальные нормализованные слова в порядке запроса;
  `count` — их число. `occurrences_count` содержит количество всех
  непересекающихся вхождений найденных слов в текст.

## `links`

**Что делает.** Извлекает HTTP- и HTTPS-ссылки из текста.

**Пример запроса.**

```json
{
  "text": "Подробнее: https://example.org/info, а также http://example.org/faq.",
  "detectors": ["links"],
  "options": {"links": {}}
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 2,
  "results": [
    {
      "name": "links",
      "detected": true,
      "confidence": 1.0,
      "count": 2,
      "details": {
        "links": [
          "https://example.org/info",
          "http://example.org/faq"
        ]
      }
    }
  ]
}
```

**Особенности.**

- Параметры не поддерживаются: необходимо передавать пустой объект `{}` либо
  не указывать `options.links` вовсе. В частности, legacy-параметр `max_links`
  отклоняется.
- Распознаются только URL с префиксом `http://` или `https://`.
- Повторяющиеся ссылки удаляются с сохранением первого появления. Знаки
  пунктуации `.,;:!?)]}` в конце URL не включаются в результат.
- При обнаружении более 100 уникальных ссылок возвращается HTTP 422; список не
  обрезается.

## `phone`

**Что делает.** Находит номера России/Казахстана, Узбекистана и Беларуси и
возвращает их в нормализованном международном формате.

**Пример запроса.**

```json
{
  "text": "Звоните: 8 (912) 345-67-89, +998 90 123-45-67 или +375 (29) 123-45-67.",
  "detectors": ["phone"],
  "options": {"phone": {}}
}
```

**Пример ответа.**

```json
{
  "has_signals": true,
  "signal_count": 3,
  "results": [
    {
      "name": "phone",
      "detected": true,
      "confidence": 1.0,
      "count": 3,
      "details": {
        "phones": [
          "+79123456789",
          "+998901234567",
          "+375291234567"
        ]
      }
    }
  ]
}
```

**Особенности.**

- Параметры не поддерживаются: передаётся пустой объект `{}` либо
  `options.phone` можно не указывать.
- Для РФ/Казахстана распознаются номера с началом `+7`, `7` или `8`; для
  Узбекистана — `+998`, для Беларуси — `+375`. Разрешены пробелы, круглые
  скобки и дефисы в ожидаемых позициях.
- Номера приводятся к международному цифровому виду (например,
  `8 (912) 345-67-89` → `+79123456789`), дедуплицируются и сохраняют порядок
  первого появления.
- Добавочные номера и несоответствующие шаблонам короткие номера не
  извлекаются. Проверка не оценивает существование или достоверность номера.
- При обнаружении более 100 уникальных номеров возвращается HTTP 422; список
  не обрезается.

## Ограничения и ошибки валидации

- `text` — строка не длиннее 20 000 символов.
- В `detectors` должен быть хотя бы один из трёх допустимых детекторов;
  повторения запрещены. Максимум — три детектора.
- Неизвестные поля и параметры, опции для незапрошенного детектора, а также
  отсутствие `blacklist.words` для детектора `blacklist` приводят к HTTP 422.
- При превышении лимита сущностей ответ имеет HTTP 422 и тело вида:

```json
{
  "detail": {
    "code": "detection_limit_exceeded",
    "message": "links detector found more than 100 unique links"
  }
}
```
